# 第10段階：単語帳の拡充とクイズ設定（mikan型）

## 目的
単語問題を増やし、ジャンル→セットを選び、出題範囲・出題形式・制限時間を設定してから始められるようにする。時間制限とコンボ表示でテンポを上げる。スクリーンショットの提出は不要。変更点、テスト結果、チェックリストの評価だけを報告すること。

## 1. ジャンルとセット
- ジャンルは5つ：基礎単語、日常単語、ビジネス単語、アドバンス単語、超アドバンス単語
- 各ジャンルに番号付きのセット（①、②、③…）を置く。1セット＝10語＝1セッション
- 今回は各ジャンル①〜③（計15セット・150語）を作る
- レベル帯の目安：基礎 A1〜A2、日常 A2〜B1（生活の場面）、ビジネス B1〜B2（仕事の場面）、アドバンス B2〜C1、超アドバンス C1〜C2
- 既存の C1① の10語は、新しい方針で作り直してアドバンス単語に統合する。語のIDは変えず、既存の回答履歴を引き継ぐ。ジャンル内での位置（①〜③のどこに入れるか）は仕様確認時に提案する
- ジャンル・セットの追加は、教材ファイルの追加だけで行えるようにする（コードの変更を不要にする）

## 2. 語のデータと品質
- 語の選定は、ライセンスを確認できるオープンな語彙リストに限る（CEFR-J、Octanove、ビジネス語彙リストなど）。使用するリストとライセンスを報告し、必要なクレジットを表示する。市販の単語帳の語順・例文・選択肢は使わない
- 各語：不変のID、見出し語、品詞、簡潔な日本語訳、英英定義、オリジナルの例文、レベル、ジャンル、セット番号、状態（unverified／verified）
- 多義語は、そのジャンル・レベルに合う意味で出題し、出題した意味を記録する
- 4択の方針（既存どおり）
  - 英→日：簡潔な訳語。誤答は同じレベル・同じ品詞の別の語の訳語から選ぶ
  - 日→英：選択肢は英単語。誤答は同じレベル・同じ品詞の別の英単語から選ぶ
  - 英→英：定義文。誤答は別の語の定義から選び、文の構造をそろえる
  - 正解の類義語、反意語、明らかに不自然な選択肢を誤答にしない。正解は1つ
  - 選択肢の長さで正解が分からないようにする（既存の検証ルールを適用）
- 自動検証に、ジャンル・セットの語数、重複、選択肢の検証を追加する

## 3. 出題の設定画面（セットを選んだ後に開く）
- 上部：ジャンル名とセット名
- 出題範囲（横に並ぶ選択肢。各項目に対象の件数を表示し、0件は選べない状態にする）
  - おまかせ：そのセットの中で、誤答・SKIP・時間切れの語を優先し、次に未学習の語
  - 苦手：現在の出題形式で、直近の回答が誤答・SKIP・時間切れの語
  - 未学習：現在の出題形式で、まだ回答していない語
  - 保存済み：保存した語
- 出題形式：英→日／日→英／英→英
- 制限時間：オフ／7秒／10秒／15秒（初期値は10秒）
- 「スタート」ボタン（主要ボタン。画面内で唯一）
- 最後に選んだ出題範囲・出題形式・制限時間を記憶する
- 第4段階のトークンと design-rules.md に従う。mikanの配色やアイコンは使わない

## 4. 時間制限とタイムバー
- 問題が表示された時点から計測を始め、回答した時点で止める。解説シートの表示中は計測しない
- 進捗バーの下に、残り時間を示す細いバーを置き、時間とともに短くなる
- バーの色はニュートラルな文字色系のトークンとする。主役色・誤答色は使わない。時間切れが近づいても色を変えない
- 時間切れは誤答として扱い、正解と解説シートを表示する。回答ログには時間切れであることが区別できる形で記録する（既存の列で表現できない場合は、方法を仕様確認時に提案する）
- ブラウザのタブが非表示の間は計測を止める
- prefers-reduced-motion では、バーの動きの代わりに残り秒数の数字を表示する

## 5. コンボ表示
- 連続で正解した数が3以上になったら、選択肢の上に「3 COMBO!」のように表示する。正解色を使い、600ms程度で控えめに出して消える
- 誤答・SKIP・時間切れで連続数をリセットする
- 結果画面に、そのセッションの最大コンボを表示する
- prefers-reduced-motion では、動きをなくして文字だけ表示する

## 6. 画面の流れ
- 単語タブ → 単語帳（5ジャンルの一覧。各ジャンルの進捗）→ ジャンルの画面（セット①〜③の一覧。ベストスコア、クリア時はチェック）→ 出題の設定 → セッション → 結果
- 既存の保存した語・組み合わせのタブ、ホームの「今日の復習」は維持する

## 7. データベース
- 出題形式に「日→英」を追加するため、answer_logs、unit_sessions、preferences の mode の制約を広げる必要がある。既存の値（ja、en）は変更せず、新しい値を追加するマイグレーションのSQLを作る
- 時間切れの記録方法によって変更が必要な場合も、同じマイグレーションに含める
- 適用済みのマイグレーションの中身は変更しない

## 8. 守ること
- design-rules.md、design-tokens.css、CLAUDE.md のルールに従う
- 既存の端末内データ、同期、記事、コロケーションの機能を壊さない
- スコープ外：AI添削、学習時間の計測、記録画面、コロケーションの追加

## 進め方（「止まる」とある工程では必ず止まること）
1. ジャンルごとのレベル帯と語の選定元・ライセンス、データ形式、C1①の統合方法、時間切れの記録方法、画面の流れ、マイグレーションのSQL案を出力して止まる
2. 承認後、マイグレーションのSQLファイルを作成して止まる（ユーザー側のClaudeが適用する）
3. 適用の報告を受けたら、「基礎①」と「超アドバンス①」の2セット（20語）の全内容（語、品詞、訳、定義、例文、3形式の選択肢）を一覧にして止まる（内容レビューのため）
4. 承認後、残り13セットを作成し、画面を実装する
5. テストを実行し、変更点とチェックリストの評価を報告する
