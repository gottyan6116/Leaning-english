# 第6.5段階 実装・検証報告

2026-10-05。対象はログイン／アカウント／学習設定／データ管理／取り込み確認。同期・データ構造・RLS・バックアップ・移行照合は維持した。

## 実装

- 独立したログイン画面。静止した淡いピンクと補色のグラデーション、最大400pxのすりガラス。非対応時および透明度を減らす設定では不透明な白いカード。
- メールフォームとname/autocomplete、パスワード右端の目アイコン、表示／非表示切替。
- invalid_credentialsは「メールアドレスまたはパスワードが違います」。通信失敗・タイムアウト・サーバー障害は「サーバーに接続できません。時間をおいて再度お試しください」。ローカル保存障害は別の日本語メッセージ。
- 認証応答から安全なcode/statusを渡すだけの最小変更。認証・同期の手順は変えていない。英語の生エラーは表示・保存しない。
- ログイン処理中はメール／パスワード／目アイコン／送信／ゲスト選択を無効化し、遅延応答による意図しない利用者切替を防止。
- アカウントではメールと学習設定・データ管理・ログアウト・このアプリについてだけを通常表示。未送信／失敗時だけ同期状態を表示。
- 学習設定は出題モード／自動送りだけを即時保存。既存の日・週目標は維持。
- 同期日時はデータ管理だけに分単位で表示。再同期／JSON書き出し／保留した取り込みもこの画面。
- 取り込みの合計は既存の重複排除済みcountsから計算。0件は非表示。内訳は詳細内だけ。旧保存形式を別区分で表示しない。照合成功時にだけ「取り込みました」をモーダル内のトーストで1回表示。
- ゲスト選択のUI設定は端末内のenglish-notes.ui.guest-choice.v1。学習データや同期対象を変更しない。
- docs/design-rules.mdにログイン限定の例外と利用者向け情報の制限を追記。

## 検証の範囲

自動テスト77項目通過、教材検証4件・0エラー・0警告。独立QAの再監査で未解決P1/P2なし。ブラウザは実際のアプリと模擬認証・模擬API、隔離したメモリ保存を使用した。実アカウントや実学習データへの変更は行っていない。ユーザー管理の接続設定は変更していない。

390×844と1280×900で確認。認証エラー、通信エラー、目アイコン、ゲストへの遷移、即時設定保存、取り込み0件／1件、保留からの再開、詳細の開閉、照合後のトースト、ログアウト後のログイン画面を確認。遅延認証時に5操作すべてが無効になることもブラウザで確認。

パスワード管理ツールは実際の保存・自動入力を未確認。フォーム構造の適合まで確認した。非対応ブラウザやOSの透明度軽減設定は実機で未確認であり、CSSのフォールバック条件を確認した。
