# 第15段階：学習時間の計測と記録画面

## 目的
利用者が「どれだけ積み上げたか」を実感でき、モチベーションにつながる学習時間を記録・表示する。放置した時間を数えないこと（頑張った実感と数字が一致すること）を最優先にする。学習時間を英語力の上達として表現しない。スクリーンショットの提出は不要。

## 1. 計測の仕組み（段階1）
### 記録の単位
- 学習の「区間」を1件の記録とする。項目：不変のID（uuid）、種類（vocab／colloc／article／listening／manual）、対象のID（セットID・記事IDなど、任意）、開始時刻、終了時刻、実際に数えた時間（ミリ秒）、記録の方法（auto／manual）、端末ID（端末内で生成したランダムな値。個人情報を含めない）、更新日時、削除日時（手動の記録の削除用）
- 1つの端末で同時に計測する区間は1つだけ

### 計測の開始と停止
| 種類 | 開始 | 停止 |
|---|---|---|
| 単語・組み合わせのクイズ | 1問目が表示された時点 | 結果画面の表示、画面の非表示、60秒間操作がない |
| 記事 | 本文が表示された時点 | 画面の非表示、3分間スクロール・タップ・キー操作がない、記事から離れる |
| リスニング | 再生した時間だけ（機能は将来。種類だけ用意する） | 一時停止・停止 |
- 無操作で止めた場合、区間の終了時刻は「最後に操作した時刻」とする（無操作の判定に要した60秒・3分は数えない）
- 解説シートを読んでいる時間はクイズの学習時間に含める（無操作の判定は適用する）
- 停止後に操作が再開されたら、新しい区間を始める（同じ区間を延長しない）
- 5秒未満の区間は記録しない。1つの区間が60分を超えたら、60分で区切る
- 画面を閉じる・別のアプリに切り替える（pagehide、visibilitychange）ときは、その時点で区間を確定し、端末内に保存する
- 無操作の時間（60秒・3分）は設定値として1か所にまとめる

### 保存
- 区間は、確定した時点で端末内に保存する（既存のオフライン優先・outbox の仕組みに従う）
- 端末内保存のキーは、既存の利用者ごとの名前空間に従う

## 2. 集計の規則（段階1）
- 日付は日本時間。週は月曜始まり。日付をまたぐ区間は、集計時に日ごとに分割する
- 同じ日に複数の端末の区間が重なっている場合は、時間軸で重ね合わせて重複を除く（二重計上しない）
- 重なった時間が異なる種類の場合、その時間は「後から始まった区間」の種類に割り当てる。種類別の合計の和が、全体の合計と必ず一致すること
- 手動の記録は時刻を持たないため、重なりの計算には含めず、その日の合計に加算する
- 集計は、表示部分と分けたモジュールにし、テストを書く

## 3. データベースと同期（段階2）
- 新しい表 study_segments を追加するマイグレーションのSQLを作る
  - 上記の項目に加え、user_id（auth.users を参照、削除時に連動）、server_updated_at（サーバー側で設定）
  - 全操作にRLS（本人の行のみ）。既存の学習表と同じ方式
  - 自動の記録は確定後に変更しない（追記のみ）。手動の記録は、更新日時が新しい場合のみ更新を受け付ける（既存の accept_newer_client_update と同じ方式）、削除は削除日時の記録で行う
  - 索引：(user_id, started_at)、(user_id, server_updated_at)
- 同期は既存の仕組み（outbox、差分取得、重なり幅）を使う

## 4. 記録画面の作り直し（段階3）
既存の記録画面は、固定のサンプル値（1時間30分、9/28〜10/3、先週比+48分など）と、禁止ルールの英字の小見出し「YOUR PROGRESS」・キャッチコピー「続けた時間を、振り返ろう。」を含むため、すべて作り直す。

上から次の順に置く。
1. 累計の学習時間（最も大きく）と、次の節目までの残り。節目は 10・30・50・100・200・300・500・1000時間。例：「100時間まであと12時間」と、節目までの進捗を細いバーで表示
2. 学習カレンダー（ヒートマップ）：日ごとの学習時間を色の濃さ5段階で表す。PCは直近約17週、スマホは約12週。0分の日は薄い灰色。日をタップ（PCはホバーも）すると、その日の日付と合計時間を表示
3. 今週の学習時間：月〜日の棒グラフを、種類別（単語・組み合わせ・記事・アプリ外）の積み上げで表示。その上に今週の合計
4. 先週の同じ期間との比較：今週の今日までの合計と、先週の同じ曜日までの合計の差（例：「先週の同じ期間より +48分」）。マイナスの場合も責める表現にしない（例：「先週の同じ期間より 20分少なめ」）
5. 種類別の内訳：今週・今月・累計の切り替え。種類ごとの時間と割合
- 学習の記録が0件の利用者には、空の枠や0だらけの表示ではなく、「学習すると、ここに記録が積み上がります」という1行と、ホームへの導線だけを表示する
- 学習しなかった日を責める表現（サボり、など）を使わない

### design-rules.md の追記
- 主役色の「達成の表示」に、記録画面のヒートマップ（主役色の濃淡5段階）と、節目までの進捗のバーを追加する。濃淡はトークンとして design-tokens.css に定義する
- ホームで追加した種類の色（単語＝ピンク系、組み合わせ＝紫系、記事＝緑系）を、記録画面のグラフと内訳でも使ってよい。アプリ外は灰色系のトークンを新設する

## 5. ホームの差し替えと目標（段階3）
- ホームの「今週の回答数」を「今週の学習時間」に差し替える（第12段階で用意した切り替えを使う）
- 学習設定に、日・週の目標（分）の入力欄を再表示する（保存済みの値はそのまま使う）
- ホームの「学習の進捗」に、目標がある場合のみ「今日 15 / 30分」「今週 90 / 150分」を1行ずつ表示する。目標がなければ表示しない

## 6. アプリ外の学習の手動追加（段階4）
- 記録画面に「＋ 学習時間を追加」の文字ボタン（主要ボタンにしない）
- 入力：日付（初期値は今日、未来の日付は不可、過去90日まで）、時間（時間と分、1分〜6時間）、種類（英会話、読書、動画・ポッドキャスト、その他）、メモ（任意、100文字まで）
- 追加した記録は、記録画面の下部に「アプリ外の学習」として一覧表示し、編集・削除できる
- グラフと内訳では「アプリ外」として自動計測と色を分ける
- 1日の合計が24時間を超える入力は保存しない

## 7. 守ること
- design-rules.md、design-tokens.css、CLAUDE.md のルールに従う
- 既存の端末内データ、同期、クイズ、記事の動作を壊さない
- 計測の処理が、クイズのタイマーや画面の応答を遅くしないこと

## 進め方（「止まる」とある工程では必ず止まること）
1. 区間の開始・停止の判定を各画面のどこに組み込むか、集計の規則、表の定義、記録画面の構成、design-rules.md の追記案を出力して止まる
2. 承認後、計測の仕組みと集計のモジュール、端末内の保存を実装し、テストを書いて止まる。テストには少なくとも次を含める：無操作で止めた区間の終了時刻が最後の操作の時刻になる、画面の非表示で区間が確定する、5秒未満を記録しない、60分で区切る、日付をまたぐ区間の分割、2台の端末の重なりの除去、異なる種類が重なった場合の割り当てと合計の一致、手動の記録の加算、週の区切り（日本時間・月曜始まり）
3. 承認後、study_segments のマイグレーションのSQLを作成し、全文をチャットに出力して止まる（ユーザー側で適用する）
4. 適用の報告を受けたら、同期、記録画面、ホームの差し替え、目標、手動追加を実装する。テストを実行し、変更点とチェックリストの評価を報告して止まる
5. 承認後、push して公開版への反映を確認する

- [ ] スマホとPCで同時に学習した時間が二重に数えられない
- [ ] 種類別の合計の和が、全体の合計と一致する
- [ ] スマホで学習した時間が、PCの記録画面に反映される
- [ ] 記録画面に固定のサンプル値、英字の小見出し、キャッチコピーがない
- [ ] 累計、次の節目、ヒートマップ、今週の積み上げ棒グラフ、先週との比較、種類別の内訳が実データで表示される
- [ ] 記録が0件の利用者に、空の枠や0だらけの表示が出ない
- [ ] ホームに今週の学習時間と、目標がある場合の進捗が表示される
- [ ] アプリ外の学習を追加・編集・削除でき、グラフで色が分かれている
- [ ] 計測と集計のテストが追加され、既存のテストがすべて通る
