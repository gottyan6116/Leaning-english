# 第13段階：ニックネームとアプリ名の変更

## 1. ニックネーム
- 保存先は Supabase Auth の user_metadata の nickname とする（supabase.auth.updateUser で更新）。データベースのテーブル・マイグレーションは変更しない
- 第12段階で追加した端末内の「表示名」は廃止し、既存の値があれば、初回のニックネームの初期値として使う（その後、端末内の値は使わない）
- ログイン後、nickname が未設定なら、1回だけ全画面の入力画面を表示する
  - 見出し「ニックネームを設定」、入力欄1つ（1〜20文字、前後の空白を除く、改行不可）、主要ボタン「はじめる」
  - 説明文は1行のみ：「ホームなどで表示されます。あとから変更できます。」
  - スキップはできない。キャンセルした場合はログアウトの扱いにする必要はなく、次回のログイン時に再度表示する
- アカウント画面にニックネームの行を追加し、変更できるようにする
- 挨拶：「こんばんは、Takaさん」の形式（スマホは2行）。未ログイン（ゲスト）は名前なしの挨拶
- PCの左ナビ下部：ニックネームを表示（未ログインは「アカウント」）
- 通信できないときは、端末内に最後に取得したニックネームを表示する
- 将来の新規登録画面でも同じ入力欄を使えるよう、入力欄は部品として作る

## 2. アプリ名の変更
- 表示上のアプリ名を「English Notes」から「【新しい名前】」に変更する
- 対象：左ナビのロゴ表記、ログイン画面、ページのtitle、manifest（名前・短い名前）、OGP、「このアプリについて」、HANDOVER.md と CLAUDE.md の名称
- 変更してはいけないもの（データが読めなくなるため）：端末内保存のキー（english-notes.* の名前空間）、同期カーソルなどの内部キー、Supabaseのテーブル名、教材のID、リポジトリ名
- 変更前に、English Notes の文字列が出てくる箇所を一覧にし、「表示上の名前」と「内部の識別子」に分けて報告すること

## 3. 不具合の確認
- アドレスが ?view=articles なのにホームが表示される場合がある。URLの状態と表示中の画面が常に一致するように確認・修正する

## 進め方（「止まる」とある工程では必ず止まること）
1. English Notes の出現箇所の一覧（表示上の名前／内部の識別子）、ニックネームの保存と表示の方法、?view の不具合の原因を出力して止まる
2. 承認後に実装し、テストを実行して、変更点とチェックリストの評価を報告して止まる
3. 承認後、push して公開版への反映を確認する
