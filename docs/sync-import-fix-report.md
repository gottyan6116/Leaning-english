# 初回取り込み失敗の修正

2026-10-05。参照スキル：supabase:supabase、systematic-debugging、test-driven-development、control-in-app-browser。独立QA再監査：残存P1/P2なし。

## 変更

- 適用済みの20261005032051_allow_unset_goal_preferences.sqlをユーザー指定の内容のまま追加。daily/weeklyはSQL NULLとJSON nullを未設定として許可し、mode/autoAdvanceのNULLは禁止。
- 取り込み時のファイルの自動ダウンロードを廃止。旧キーと取り込み前スナップショットを端末内に保持し、完了後もスナップショットを保持。手動JSON書き出しは継続。
- 行のPOST送信で400〜499（401以外）を受けた版は端末内の送信不能データとして保持し、自動再送対象から除外。内容を変更した新しい版は送信対象に戻る。
- 通信失敗・500番台は再送、401は認証更新。認証更新自体の400は行の拒否として分類せず、再ログイン後に送信する。
- データの管理に送信不能件数と詳細を表示。送信の破棄は確認して行い、端末内の学習記録は削除しない。
- 部分取り込みは対象IDごとの結果と成功／失敗件数を内部保存し、「一部を取り込めませんでした」と表示。確認できた全対象だけを完了とする。未確認は成功と表示しない。
- 読み込みバージョンを20261005-import-fixへ更新。
