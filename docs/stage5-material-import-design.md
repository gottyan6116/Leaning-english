# 教材取り込みと選択肢ID：追加仕様

2026-10-04。記事1本目の修正版とともにレビュー。ランタイムは内容承認後に実装する。

## 教材をコードから分離

- materials/articles/*.json：記事。
- materials/vocabulary/*.json：ユニット。現在のC1①のJS内データは承認後にJSONへ移す。既存JSと既存IDは互換性を維持する。
- materials/manifest.json：検証済みの教材ID、パス、種別、版、公開日時、内容のハッシュ。検証スクリプトで生成する。
- 教材の追加・修正はJSONだけで行う。コードに教材のID一覧を書かない。検証・索引生成・Git pushは必要だがアプリコード変更は不要。

既存の保存語・ログ・モード別ベストはIDを維持する。C1①の使い方は今回は追加しない。残り90語も作成しない。

## 公開日と検証

全教材にpublishedAtを持たせる。ISO8601のタイムゾーン付き日時。内容承認前はNULLのまま、下書きは公開索引から除外。公開対象はstatus=checked、公開日時が現在時刻以下の教材のみ。出典のpublishedAtとは区別する。

未来公開の確認済み教材は索引に含め、表示時に公開日時で絞る。公開日が来たときにコードを更新する必要はない。Git上の静的JSONは公開ファイルなので、これは表示時期の制御であり秘匿ではない。

取り込み前に教材フォルダ全体を検証する。ID・出典・段落参照・単語・4択・正解ID・長さ・ユニット語重複・公開日時・使い方の項目を検証。エラーなら索引を更新せず処理を停止。警告は内容レビュー対象。検証済みJSONとハッシュを索引に記録し、読み込み時に不一致の教材は取り込まない。CIにも同じ検証を組み込み、手動で検証せず編集したファイルをそのまま表示しない。

既存C1①はユーザーの許可に従い下書きのままJSONへ移行し、公開日時を設定した。確認済みに変更しない。教材の正はJSONで、旧JSは初期化・旧保存語の互換用に残す。

## 4択の並べ替えと採点

既存choices配列とanswerIndexは互換性のため残す。追加項目はchoiceIds（各選択肢の固定ID配列）とcorrectChoiceId。

- IDは教材編集で順番を変えても変更しない。選択肢の意味自体を差し替える場合は新しいIDを付ける。表示番号をIDに流用しない。
- 出題時に{id,text}をFisher–Yatesで並べ替え、その問題の回答完了まで表示順を固定。再描画で再シャッフルしない。
- 採点はselectedChoiceId === correctChoiceId。表示indexと旧answerIndexを比較しない。
- 回答ログに端末発行eventId、questionId、selectedChoiceId、correctChoiceId、教材版を追加。旧selectedIndexと既存項目を削除しない。SKIPはselectedChoiceId=null。
- 1〜4キーは現在の表示配列の0〜3番目の選択肢IDを送る。
- 記事の語彙・上級語彙集・内容理解で同じ共通処理を使う。

検証テストは4択の全24通りで同じ正解IDだけが正解になること、誤答IDが正解にならないこと、保存ログが位置ではなくIDを持つこと、キーボードが表示順に対応すること、二重回答を保存しないことを確認する。両モードの全24通り・全表示位置、二重回答、記事設問のID保存までテスト済み。

## 使い方

usage.status=unverified、combinationsは3〜5件。form、pattern、meaningJa、nuanceJa、example、exampleOrigin、statusを持つ。各項目statusもunverified。commonMisuseは確証がある場合だけ1件、なければNULL。

使い方のユーザー確認状態は記事本文の承認状態と別。今回は表示しないため、本文が承認されても使い方を勝手に確認済みにしない。例文・説明は独自作成。辞書のコロケーション例文を転載しない。
