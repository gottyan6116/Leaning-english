# 第16段階：表現の引き出しを増やすページ（表現）

## 目的
同じことを伝える言い方を、場面・伝えたいこと・相手に与える印象に応じて選べるよう、表現の「引き出し」を増やす。英語に上位互換の表現はほとんどなく、違いは場面と響きにある、という考え方を全体の前提にする。「基本表現を上級表現に置き換える」という見せ方はしない。スクリーンショットの提出は不要。

## 1. ナビゲーション
- 下部タブ（PCは左ナビ）の「リスニング」を「表現」に置き換える。リスニング機能は、将来、記事の読み上げとして記事のページに入れる（今回は作らない）
- 既存のリスニングの画面に機能がある場合は、置き換える前に内容を報告して止まること

## 2. 機能（16）
| 分類 | 機能 |
|---|---|
| 考えを伝える | 意見を言う、賛成する、反対する、提案する |
| 確かめる | 質問する、聞き返す・理解を確認する |
| 頼む・断る | 依頼する、断る、保留する（考える時間をもらう） |
| 会話を進める | 相づち・反応する、話題を変える・戻す |
| 気持ちを伝える | 感謝する・謝る、褒める |
| 仕事を進める | 交渉する、進捗を報告する |
| 人と関わる | 誘う |
- 各機能に6〜9個の表現。丁寧さ（カジュアル／中立／丁寧）、強さ（控えめ／中立／はっきり）、場面（仕事／日常／両方）が偏らずに散らばるようにする

## 3. 表現のデータ
各表現に持たせる項目：
- 不変のID、機能、表現（例：I'm inclined to think…）
- 丁寧さ、強さ、場面
- ニュアンス：違いや使う場面を説明する（第14段階の基準。日本語の意味の言い換えだけの説明は不合格）。例：「断定を避けて、考えの方向だけを示す。相手に反論の余地を残すので、議論の途中で使いやすい」
- 注意点（任意）：使いすぎ・場違いになる場面。例：「日常の雑談で使うと、大げさに聞こえる」
- 例の会話：2〜3往復の短い会話（オリジナル）
- 近い表現：同じ機能の他の表現のID（最大3つ）と、違いの一言
- 状態：unverified／verified。unverified には画面に「確認中」を文字だけで表示する
- 市販の表現集・辞書の例文や表現の並びを転載しない
- 検証スクリプトに、項目の不足、ID・表現の重複、近い表現のIDの存在、言い換えだけのニュアンスの検出を追加する

## 4. 画面
### 表現タブのトップ
- 分類ごとに機能を並べる。各機能の行に、機能名と「引き出し n / m」（使える表現の数／その機能の表現の総数）と細い進捗バー
### 機能のページ（表現マップ）
- 表現を、丁寧さ×強さの表として並べる（スマホでは、丁寧さごとの縦のリストに切り替える）。場面（仕事／日常）で絞り込める
- 表現をタップすると、詳細（ニュアンス、注意点、例の会話、近い表現）を開く
- 各表現に保存（しおり）。保存は組み合わせと同じく saved_words に「expr:<表現のID>」のキーで保存し、端末間で同期する（第14段階と同じ方式）。単語・組み合わせの一覧や件数に混ざらないよう、種類で区別する
- ページ下部に主要ボタン「この機能を練習する」

## 5. 練習（クイズ）
既存のクイズのセッション（タイマー、コンボ、結果画面）を再利用する。1回10問、その機能の表現から出題する。
| 形式 | 問い方 |
|---|---|
| 場面の判断 | 場面の説明（例：上司へのメールで反対意見を伝える）を見て、最も適切な表現を選ぶ |
| 響きの判断 | 4つの中から、その場面で失礼・場違いに聞こえるものを選ぶ |
| 丁寧さの並べ替え | 4つの表現を、カジュアルから丁寧の順に並べる（スマホはタップの順番、PCはドラッグとキーボードの両方で操作できる） |
| 会話の穴埋め | 会話の流れに合う表現を選ぶ |
- 問題は表現ごとに人が作った固定の問題とし、自動生成しない
- 各問題に「正解の理由」と「他の選択肢が合わない理由」を持たせ、解説シートに表示する
- 正解が1つに決まらない問題を作らない。場面の説明に、正解を決める条件（相手、媒体、伝えたい強さ）を必ず含める
- 選択肢の位置は毎回ランダム、採点は選択肢のIDで行う

## 6. 引き出しの数
- 表現ごとの状態は、既存の単語と同じ規則（未学習／復習予定／学習中／定着）で、回答ログから算出する
- 「使える表現」は、状態が「定着」（直近2回連続で正解）のもの
- 将来、AI添削で正しく使えた表現も加算できる作りにする（今回は作らない）
- 間違えた表現は、おまかせ復習とホームの復習件数に含める

## 7. データベース
- answer_logs の kind に、表現の練習の値を追加する必要がある。mode の扱い（既存の値を使うか、新しい値を追加するか）も含めて案を出し、マイグレーションのSQLを作る
- 第15段階の学習時間の計測に、表現の練習の種類を追加する（第15段階が完了している場合）
- 適用済みのマイグレーションの中身は変更しない

## 8. 守ること
- design-rules.md、design-tokens.css、CLAUDE.md のルールに従う
- 既存のデータ、同期、他の画面の動作を壊さない
- スコープ外：AIによる言い換え・書いてみる（AI添削の段階で追加）、記事の中の表現へのタグ付け、リスニング

## 進め方（「止まる」とある工程では必ず止まること）
1. リスニングの画面の現状、データ形式、画面の構成、練習の形式ごとの出題と採点の方法、引き出しの数の算出方法、データベースの変更案を出力して止まる
2. 承認後、マイグレーションのSQLを作成し、全文をチャットに出力して止まる（ユーザー側で適用する）
3. 適用の報告を受けたら、まず「意見を言う」「反対する」「依頼する」の3機能だけの表現と問題を作り、一覧ファイル（表現、丁寧さ、強さ、場面、ニュアンス、注意点、例の会話、近い表現、問題と正解・理由）にしてパスを報告して止まる（内容レビューのため）
4. 承認後、残り13機能を作成し、画面と練習を実装する。テストを実行し、変更点とチェックリストの評価を報告して止まる
5. 承認後、push して公開版への反映を確認する
