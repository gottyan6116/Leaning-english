# 第6段階：同期の実装・検証

2026-10-05。参照スキル：supabase:supabase、test-driven-development、verification-before-completion。開発・UI実装を分担し、QAが独立してソースと全テストを確認。未解決のP1/P2指摘なし。

## 反映した内容

- 適用済み3本のマイグレーション履歴にファイル名を一致させた。最初の2本はSHA-256でも内容不変を検証。
- 認証設計・手順書をメール＋パスワードへ変更。アカウント内にログイン／ログアウト、同期状態、明示的取り込み、再同期、JSON書き出しを追加。
- 既存の端末保存キーを保持し、ゲスト／本人の名前空間へ移行。1つの保存単位で学習値とoutboxを原子的に記録。
- 回答・完了セッションは追記、保存語・設定・読了・意見は更新日時による統合。保存解除・意見削除はtombstone。教材と既存の状態算出ルールは維持。
- テーブル別サーバーカーソル、10分の重なり、主キーを使うページ取得。送信中に変更された新しい版のoutboxを残す。
- 容量不足を注入して認証と保存先が分離する不具合を検出・修正。利用者切替の復元と、通信／応答前の所有者一致をテスト。

## 実Supabaseでの読み取り専用確認

3本の履歴番号、publicの6学習表＋privateの許可表のRLS、auth.uid()=user_idのポリシー、4可変表の更新トリガー、全表の受信時刻トリガーを確認。許可表SELECTはsupabase_auth_adminのみ。Hookはemail/google判定、SECURITY INVOKER、anon/authenticatedの実行権限なし。許可メールの実値・学習内容は問い合わせていない。HookがAuth設定画面で実際に有効か、メール確認OFF等はユーザー報告に基づく。

## 自動検証（実端末ではない）

- Nodeテスト68項目通過。既存機能、保存アダプター、同期transport、2クライアント統合、SQLファイルの内容不変を含む。
- 隔離PostgreSQL45項目通過。別利用者の読み書き拒否、anon拒否、古い／同時刻の更新拒否、再送重複防止、許可外登録判定、FK連鎖など。
- 教材自動検証4件、エラー0・警告0、manifest一致。
- 同期は2つの独立した保存領域と実AppState／QuizStoreを使い、模擬RESTサーバーで相互反映を検証。スマホ／PC実機での確認ではない。
