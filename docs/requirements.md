# 個人用英語学習アプリ 要件・ページ構成案

品質: ドラフト / 2026-10-03

参照スキル: superpowers:brainstorming、secretary/intake-and-memory、product_ux/ux-design、qa/output-review。
実行深度: M。新規アプリの設計段階。決定済みの要望と今回の提案を分け、実装は別工程とする。

## 論点ブリーフ

- 背景: 本人（B2〜C1）を中心に、将来は一般公開を視野にA2〜C1へ対象を広げ、仕事・読解・日常文化の英語を学べるようにする。
- 目的: 実際の内容を読む・聞く・保存する・復習する一連の学習を、スマホとPCで継続できるようにする。
- 主要論点: 無料運用を優先しながら、事実に基づく教材と個人の復習履歴をつなぐ初期アプリを、どの範囲・ページ構成で作るか？
- サブ論点: 学習導線、教材品質、復習、計測と同期、教材補充、無料制約。
- 初期仮説: 教材を事前に作成・確認して取り込み、アプリは閲覧・復習・記録・予約公開を担うと、運用と品質を管理しやすい。
- スコープ: 合意済み要件の整理、初期範囲の提案、受入条件、教材形式案。
- 非スコープ: コード作成、クラウド登録、公開、実教材制作、費用が発生する契約。
- 完了条件: 決定事項と未確定事項を識別でき、ページ構成と初期範囲をユーザーが判断できる。
- 検証: 会話との照合、UXレビュー、QAレビュー。実装・無料運用は未検証。

## 1. 決定済みの要件

| 項目 | 合意内容 |
|---|---|
| 対象 | 本人（B2〜C1）中心、将来は一般公開を視野にA2〜C1 |
| 学習分野 | 仕事、ニュース・教養の読解、日常・文化をバランスよく |
| 端末 | スマートフォンとPCを同程度使用 |
| ログイン | Googleアカウント。同じ学習記録を端末間で同期 |
| 語彙 | 用意された上級語彙集と、記事から保存する単語・表現の両方 |
| 手入力 | アプリ外で出会った単語・表現も追加可能 |
| 4択 | 英語→日本語、英語→英語の2モード |
| 復習 | おまかせ復習を基本とし、保存したものをいつでも復習可能 |
| 記事 | 実在する記事・資料の事実に基づく。意味を保って英語表現・難易度を調整可能 |
| 出典 | 本文ページに出典元・引用元・原文リンクを必ず表示 |
| 長さ | 本文を読む目安は3〜5分。語彙確認・音声練習は別 |
| リスニング | 記事の読み上げと、仕事・日常の会話教材 |
| 聞き方 | 問題モードと自由練習モード |
| 学習記録 | アプリ内は自動計測。アプリ外の学習は手動追加 |
| 目標 | 日・週それぞれ任意設定 |
| 記事更新 | 確認済み教材をまとめて登録し、週3本ずつ公開 |
| クラウド | Cloudflareを使用し、追加のクラウド・API課金を発生させないことが初期制約。成立は技術検証が必要 |
| 追加運用 | 今後エージェントへ教材追加を依頼できる登録形式を用意 |

## 2. ページ構成の提案

主要な入口は「ホーム・単語・記事・リスニング・記録」。保存一覧は単語ページ内の独立して開けるページとし、ホームと記事からも直接開ける。設定はアカウントメニューに置く。

| ページ | 目的と主要操作 |
|---|---|
| ホーム | 今日の復習を開始、続きの教材へ戻る、新着記事、日・週の目標進捗 |
| 単語・表現 | 上級語彙集、保存一覧、手入力、検索、分野・苦手で絞り込み |
| 復習画面 | 出題モード選択、4択、意味・例文・解説、結果確認 |
| 記事一覧 | 3分野、タイトル、出典媒体、元記事公開日、教材公開日、読む時間の目安 |
| 記事本文 | 英文、冒頭の出典情報、原文リンク、単語・表現保存、音声への移動 |
| リスニング一覧・練習 | 記事音声と会話。問題／自由練習、速度変更、スクリプト切替、一文再生 |
| 学習記録 | 日別グラフ、週・月の集計、種類別・自動／手動の内訳、手動追加・編集 |
| 設定 | 日・週の目標、アカウント、学習設定 |

スマホは下部ナビゲーション、PCは左側ナビゲーションを初期案とする。本文と設問は読みやすい幅に保ち、保存操作は両端末で利用可能にする。

## 3. 学習フローと復習の提案

基本の流れ: ホーム → おまかせ復習 → 短い記事 → 気になる表現を保存 → 同じ記事の音声 → 記録確認。
単語・記事・音声は個別にも開始可能とし、順番の強制はしない。

- 保存項目は原形／見出し、意味、例文、メモ、出典リンクを持つ。同じ表現の別文脈は例文として追加し、意味の違いを保持する。
- 手入力は語句だけで下書き保存可能。意味・例文の確認前は一覧で「要確認」と表示する。
- おまかせ復習は、間違いと前回学習からの経過を基に次回を調整する。具体的な間隔・習得判定は技術設計で決める。
- 4択は必要に応じて例文を添え、品詞・意味の範囲をそろえ、正解が一つになることを事前確認する。
- 英語→日本語と英語→英語の成績は分けて保持する。
- 手入力項目は、有効な意味・解説・4択がそろった後に問題復習へ入れる。それまでも一覧で読み返せる。アプリ内AIで即時生成することは初期必須要件にしない。
- 手入力語彙の補完は、対象をファイルで書き出す → エージェントに意味・例文・問題の補完を依頼 → 内容確認 → 取り込み、を初期案とする。記事に属さない単語集や個別語彙も取り込める形式を用意する。補完依頼は自動送信しない。

## 4. 記事・音声の品質条件

- 根拠資料を実際に確認して作る。出典リンクだけを付けて内容を推測することは認めない。
- 数字・日付・人名・因果関係・不確実性を保ち、事実／原著者の意見や予測／教材用補足を区別する。
- 「出典に基づく学習用編集版」と表示する。直接引用は編集文と区別する。
- 出典欄はタイトル、媒体・機関、著者（確認できる場合）、公開日（不明なら不明表示）、原文リンク、確認日を持つ。
- 複数出典を使う場合は本文の該当内容と各出典を対応づける。引用箇所は引用元を特定する。
- 元記事の公開日と教材の公開日は別に持つ。古い資料を新しいニュースとして表示しない。
- 出典の有無と教材掲載の可否は別途確認する。無断の全文転載を前提にしない。
- 記事音声は本文と一致させる。音声・一文再生に必要なタイミング情報の準備方法は検証する。
- 会話は「学習用の架空の会話」と表示。実人物の発言として創作しない。事実的主張を含む場合は出典を付ける。
- 音声が準備できない教材は状態を表示し、再生できるように見せない。
- 理解度問題は本文／音声だけで答えられ、正解根拠と説明を持つ。

## 5. 学習時間・目標の提案

時間は成果そのものではなく学習量として表示。復習正答率と記事・音声の問題成績は別表示とし、CEFR上達を直接推定しない。

| 種類 | 計測の初期案 |
|---|---|
| 単語 | 回答・解説確認の活動時間。長い無操作は停止 |
| 記事 | 読書開始から。非表示時は停止。長い無操作では継続を確認し、読む時間を一律に除外しない |
| 音声 | 実際に再生した経過時間。反復を含む。停止・読み込み待ちは除外 |
| 自由練習 | シャドーイング等の練習タイマー |
| 手動 | 日付、開始時刻・所要時間、種類、任意メモ。入力前に自動記録との重複確認 |

合計は同時に発生した時間の重なりを除いた経過時間。記事＋音声、スマホ＋PCでも二重計上しない。種類別は重複しない配分規則を定める。音声を聞きながら記事表示の場合は音声に配分する案。
日付の区切りは日本時間。日・週の目標は片方だけでも設定可能。週の開始曜日・無操作の閾値・端末間重複の解決規則は設計時に確定する。

## 6. 教材追加の型と運用

提案: 固定形式の教材ファイルと音声を、一括取り込みできるようにする。最初はファイル運用とし、大きな編集管理画面は後回し。

| 教材の項目 | 内容 |
|---|---|
| 識別・版 | 変わらない教材ID、版番号、記事／会話の種別 |
| 表示情報 | タイトル、分野、難易度の目安、読む時間 |
| 本文 | 段落または文ごとのID付き英文 |
| 出典 | 出典情報、対応する本文・引用箇所、確認日 |
| 語彙 | 単語・表現、意味、文脈、例文、2モードの4択と解説 |
| 理解度 | 設問、選択肢、正解、本文の根拠 |
| 音声 | ファイル参照、スクリプト、一文再生の位置情報 |
| 公開管理 | 下書き／確認済み、公開日時、確認記録 |

作成 → 事実・出典・設問確認 → 取り込み検証 → 公開日設定 → 週3本表示。
週に各分野1本を初期案とする。具体的な曜日・時刻は未決定。12本で4週間分の準備例になる。
取り込みは同じ教材IDを重複作成せず、修正時も保存語彙と成績への参照を保つ。未確認・出典不足・正解不備は公開対象外。
予約公開は、閲覧時に公開日時を判定する方式でも成立するため、MCPや常時実行するAIを必須にしない。実装方式は後で選ぶ。
エージェントへの追加依頼時に教材作成・検証・取り込みを実行する。定期的な自律作業や外部サービスへの書き込みは、この会話の合意だけで設定済みとは扱わない。

## 7. 初期版と後続の提案

初期版は、合意した学習の流れを少量の教材で一通り使える形にする。

1. Googleログインと本人限定利用、学習データの同期。
2. 上級語彙集、保存一覧、手入力、2種類の4択、おまかせ復習。
3. 出典付き記事、3分野の一覧、記事内保存、予約公開。
4. 記事音声と会話、問題と自由練習、速度・スクリプト・一文再生。
5. 学習時間の自動・手動記録、日別グラフ、日・週の目標。
6. 教材・音声の一括取り込みと公開前検証。

動作確認用の教材数は少量で開始し、実際の公開前に必要な在庫を用意する。教材の本数・語彙数は未決定。
後続候補: 大きな教材編集画面、アプリ内での即時AI生成、発音採点、通知、完全オフライン。これらは今回の必須要件に含めない。

## 8. 検証・受入条件

- 同じGoogleアカウントで、スマホの保存語彙・成績・目標をPCから確認できる。
- 学習時間、手動記録、記事・音声の学習状態も同期する。別端末の編集や通信再送で記録が重複せず、保存完了と同期待ちを区別して表示する。
- 本人以外は個人の学習履歴へアクセスできない。Googleログインだけで本人限定とみなさない。
- 記事から単語・複数語表現を保存でき、手入力した項目と同じ一覧で見られる。
- 2モードの4択が正しく採点され、誤答が以後の復習へ反映される。
- 記事本文ページに出典・引用元が表示され、原文リンクを開ける。
- 確認済みの予約教材だけが公開日時以降に表示される。
- 音声・本文・設問が一致し、問題／自由練習を切り替えられる。
- 画面放置・音声停止・同時学習を試して時間が意図どおり記録される。
- 手動記録を編集・削除でき、重複確認と日・週の集計が一致する。
- 空の保存一覧・未配信記事・通信失敗・同期失敗・無料枠上限でも状態を説明し、失敗を成功として表示しない。
- スマホのタップ、PCのキーボード操作、文字サイズ、読み上げラベルを確認する。

## 9. 未確定・次アクション

- 技術構成、Google認証、保存容量、無料枠上限時の挙動を開発工程で検証する。有料プランや独自ドメイン購入は前提にしない。追加のクラウド・API課金なしで成立しない機能は代替方式または保留とする。現在利用しているエージェントの契約費用まで無料になる意味ではない。
- 音声の無料生成・品質・保存方法・一文再生・バックグラウンド再生を検証する。端末読み上げと保存音声は同じ品質とはみなさない。
- 具体的な記事ソース、利用条件、初期教材数、公開曜日、UIの見た目を決める。
- この文書は設計レビュー用。ユーザーの修正を反映した後、実装計画に進む。

## 10. 今回の学び

記事の更新頻度と生成頻度は分けて設計できる。事前確認した教材の予約公開により、学習の継続と出典確認を両立させやすい。
